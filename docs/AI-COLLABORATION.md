## 日常执行与审查

`需求 → 复用或创建任务工作区 → 当前模型开发与定向验证 → 固定候选 / Draft PR → 按风险自审或独立审查 → 在已有授权范围内合并 / 发布`

- 同目标反馈继续原任务；同会话身份和归属未变时复用已核验上下文，变更处看 diff。新会话重新核对现场。
- 文字、状态修订由当前模型自审。普通产品改动先说明影响及验证覆盖；存在关键覆盖缺口、复杂跨模块影响或用户要求独立审查时再启动，不强制使用某一家模型或 Web 桥接。
- 首次独立审查使用未继承开发历史、未参与实现的审查上下文。已有独立审查任务可继续复核修复增量与直接回归；修改代码的审查者不能再独立验收自己的改动。
- 新 Head 需要明确覆盖该 SHA 的结论；未改变的原始证据可注明适用范围后复用。状态、注释或无关文件变化不要求重跑全套验证。
- 高级独立审查仍由用户选择模型并启动。执行者一次准备完整入口、固定 SHA、风险和证据；复审沿用原审查任务，不反复要求用户新开对话。具体权限边界以 AGENTS 第 2.6 节为准。
- 开发隔离测试按需立即运行；900 秒自然周期约束仅适用于生产调度和相应生产验收。确定性开发测试无需等待生产周期。
- GitHub 提供实时 PR、Head、CI、合并状态；接续文件记录目标、决策、未完成和证据入口，历史快照明确范围，不追赶瞬时状态。
