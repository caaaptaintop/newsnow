# 本地 Codex 与 GitHub：使用说明

用户在固定项目入口新开对话，直接提需求、看结果、给修改意见；分支/worktree、Issue、提交、PR 和进度由当前选定模型管理。完整规则见 [AGENTS.md](../AGENTS.md)，本文件提供使用示例与验收入口。

## 日常流程

`需求/反馈 → 自动定位或新建任务工作区 → 当前模型本地开发与验证 → 展示结果并修改 → 固定候选与 Draft PR → 独立审查 → 满足授权后合并/发布`

- “继续调整这个功能”：先核对目标，继续已有任务；不因新对话重复建分支。
- “增加一个独立功能”：先查已有 Issue，再为独立目标安排分支和工作树。
- “切换模型后继续”：原生或网页模型接续同一目标；开发模型与独立审查各有职责。
- 收到“需要高级独立审查”提示时，由用户在 Codex 新审查对话选择并调用网页模型；模型自行读取已准备的 Issue/PR 材料，具体边界见 AGENTS 第 2.6 节。
- 入口显示 main 时，模型仍可在核实后的任务目录执行；界面分支不等同于实际工具目录。

## 五个冻结场景与试行验收

沿用 Issue #79 的五场景，仅在 newsnow 试行；用户确认实际体验后才能定版或推广。验收区分真实探针和推演，不为测试虚构真实任务。

| 场景 | 预期行为 | 验收方式 |
| --- | --- | --- |
| 从 main 新对话继续已有治理任务，入口有历史未跟踪文件 | 找到既有 Issue/PR/worktree，保留入口文件 | 真实入口只读发现与哈希核验 |
| 在其他任务分支提出独立需求 | 查重后从明确 main 基线创建新分支/worktree | 固定输入推演，不为测试虚构真实 Issue |
| 对已有结果提修改意见或切换开发模型 | 继续原任务，两类模型均可开发 | 文档交叉检查及独立 review |
| 目标有未知 dirty/其他写者，或映射过期 | 复核归属；暂停冲突写入；过期映射重新发现 | 风险场景推演，不声称真实并发实测 |
| 从固定入口第一次开始，未手选分支 | 读入口指引、过身份门、自动绑定目标；错误身份停 | 新鲜上下文只读探针及原身份门正负例 |

阶段进度见 [PROGRESS.md](../PROGRESS.md)，本阶段增量与下一动作见 [HANDOFF.md](../HANDOFF.md)。本机路径和入口备份见固定项目入口 `.local/CONTEXT.md`；这份本机映射不随 PR 自动分发。

## 工作目录遗漏复核：五个冻结场景（Issue #82）

这是对 Issue #81 真实调用错误的 NewsNow 单项目试行。执行边界只由 AGENTS 第 1.1 节定义；身份脚本保持不变。创建与核验使用两次工具调用，核验工具的 `workdir` 与预期根目录都绑定原目标。

| 场景 | 预期结果 | 验证方式 |
| --- | --- | --- |
| 已核验入口创建目标成功，漏设 workdir，在入口得到唯一 root mismatch | 只读核对原目标后，允许纠正 workdir 复核一次 | #81 原工具记录；隔离 Git 工作树复现 |
| 创建后第二次调用显式绑定目标 | 第一次核验通过，不使用失败恢复 | #82 本会话真实创建与核验记录 |
| fork、remote 不一致、多 remote、凭据污染或身份不可读 | 停止，不允许限定复核 | 原身份门拒绝测试及条款检查 |
| 目标缺失、被替换、共同仓库/分支/HEAD 不匹配、证据不足或未知写者 | 停止，保留现场 | 条款逐项推演；不声称模拟了真实并发 |
| 唯一复核仍失败或历史已使用一次 | 立即停止，跨轮不重置次数 | 原错误身份拒绝测试与次数条款检查 |

隔离测试验证身份脚本在错误 cwd 拒绝、正确 cwd 通过及原安全拒绝条件；次数限制、证据归属和写者判断属于模型流程约束，测试通过不代表这些约束已自动执行。试行体验与高级独立审查待完成。
