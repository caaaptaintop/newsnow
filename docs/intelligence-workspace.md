# 个人信息情报站：主题工作台

## 本次变化
首页 `/` 改为一级主题导航、二级栏目侧栏、右侧搜索和组合筛选、情报卡片。原始 NewsNow 热榜保留在 `/c/hottest`，原健宁选题页保留在 `/c/health`。

建筑栏目：智能建造、好房子、智慧建筑、绿色低碳、城市更新、建筑工业化、综合政策与标准。政策/通知/标准同时具有独立的信息类型维度。健康保留 `shared/topics.ts` 的八条编辑选题线，不改动 `server/api/topics/health/classify.post.ts` 的原有规则。

同一维度多选是“或”，不同维度之间是“且”；搜索继续受当前主题、栏目及筛选限制。搜索状态写入 URL，可收藏与分享。类别支持一个主栏目和多个相关栏目；全部信息按原文地址、明确同名同日转载规则去重。发布日期缺失不拿采集日期代替。发布地区/城市是机构所在地，并非政策适用范围。

## 信息源
`shared/official-sources.ts` 注册了 54 个住建官方机构入口：1 个部级、31 个省级（含直辖市）、22 个重点城市相关机构（武汉同时覆盖自然资源和城乡建设局、住房和城市更新局）。北京、天津、重庆不重复建立城市记录。另保留 AI/财经既有 NewsNow 适配器；健康沿用原有热榜来源。

来源名称与省级入口根据住建主管部门公开入口核对。上海主动公开文件、江苏信息公开、深圳通知公告等设有明确栏目入口。其余从各机构官网自身导航识别通知公告、政策文件、标准等栏目。`enabled: true` 只表示允许尝试采集，绝不代表已抓取成功。每个来源的成功、部分完成、失败、待采集状态由真实运行产生，可在页面“信息源”查看。

新增来源：在上述配置文件添加唯一 ID、机构名称、官方 home、发布地区/城市、栏目 URLs。禁止配置任意用户传入 URL；重定向必须仍属已配置同一机构域名。正文适配器位于 `server/utils/intelligence-parser.ts`。动态接口、验证码、防护页面不能靠填入网址解决，运行时会标注失败，需要增补该站专用适配器。不绕过验证码。

## 采集、AI 与存储
`GET /api/intelligence?topic=building|ai|finance` 返回已入库信息与来源状态。
`POST /api/intelligence/refresh` 只接受 `{ "sourceId": "official-shenzhen" }` 等已配置编号，不接受 URL、自定义提示词或模型。

官网列表 → 规范化 URL → 增量候选 → 正文/附件链接提取 → Workers AI 分批语义分析 → 严格字段校验 → D1 入库。复用现有 `AI` 绑定与 `healthTopic.aiModel`，无新增第三方密钥。AI 不可用时不降级为关键词结果。正文未识别或获取失败时，只分析标题并显示“仅依据标题分析”。附件保留链接，未读取附件不生成附件摘要。

D1 复用 `NEWSNOW_DB`，运行时通过 `CREATE TABLE IF NOT EXISTS` 添加独立情报表，不改写已有 NewsNow/健康表。数据库不可用时页面明确提示临时缓存；定时流程拒绝将此情形当作持久采集成功。

每次每来源最多处理 24 条未分析候选，单批 AI 8 条、最大并发 3 组，已判定候选按版本、模型和标题缓存 7 天，减少重复调用。成功来源间隔 6 小时，失败/部分完成最短 30 分钟再试；在途请求合并。本次只采集已配置栏目当前可见列表，没有回填所有历史分页。正文最多提取有限文本片段供 AI 分类，长文摘要仅基于已提供片段。当前工作台加载最近 5000 条；超过后显示范围提示，不声称搜索了全部历史档案。

`Refresh intelligence sources` 工作流每 6 小时执行一次，也在原 Cloudflare 部署工作流成功后执行，留下每个来源实际采集状态。页面首次空库仅启动少数高优先级来源；“同步信息”检查当前主题所有来源，受共享缓存限制。

## 验证与回滚
`pnpm exec vitest run test/intelligence.test.ts` 覆盖来源计数、日期、SSRF 域名限制、栏目与多维筛选、转载去重、官网 HTML 解析、AI 输出校验。CI 执行 Cloudflare 构建和项目 typecheck。

回滚本功能提交可恢复原首页。新增 D1 表为独立表，回滚无需删除表；健康 AI 代码与原有缓存格式未改变。
