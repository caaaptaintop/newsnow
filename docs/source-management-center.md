# 信息源管理中心

## 页面与权限

`/internal/sources`：左侧主题，右侧当前主题来源健康表；`/internal/api/sources`：同路径范围下的管理读写接口。

Cloudflare Access 应用保护 `news.capx-ai.com/internal` 及子路径，不是整个公开站。页面和 API 都独立校验 RS256 JWT、issuer、audience、exp/iat/sub 和精确管理员邮箱。缺少必要变量失败关闭为404，缺少断言401，非法断言403。写请求要求同源 Origin、JSON及48KiB请求上限。网页脚本使用每响应随机 CSP nonce。不存在通过请求传入公钥/测试身份绕过鉴权的入口。

运行变量：

- `SOURCE_ADMIN_ACCESS_TEAM_DOMAIN`：`<team>.cloudflareaccess.com`，可带 HTTPS 前缀。
- `SOURCE_ADMIN_ACCESS_AUD`：此 Access Application 的64位十六进制 audience。
- `SOURCE_ADMIN_EMAILS`：逗号、分号或换行分隔的精确邮箱白名单；部署时作为 Secret，不写入 Git、日志或公开证据。

这不开放访客登录、访客管理入口、AI 设置，也不启用非建筑主题的采集或公开。其他已定义主题可查看和保存草稿；未启用的结构化读取器不会伪造通过。

## 配置流程

1. 编辑官网与明确栏目，保存草稿。使用当前草稿哈希和活动版本进行并发守卫；旧标签页不能覆盖新修改。
2. 测试会先保存对应草稿。官方网页仅顺序、有限请求、内存解析；不调用AI，不保存正文/完整HTML/附件字节。每栏目最多五条标题、原链接和可信列表日期样本。管理员必须确认样本是否属于目标栏目；HTTP200和解析到文章不能自动证明内容符合意图。若云端仅因 Cloudflare DNS（例如 530/1016）无法读取，而生产采集实际运行在 Mac，则该测试保存为“等待 Mac 复核”，发布仍保持禁止。原 900 秒 worker 在自然周期读取完全相同的草稿哈希/活动版本，用真实生产解析器测试后通过既有 Ed25519 签名后台接口写回结果；版本变化、失败或非同一草稿均不能变成可发布测试。不新增第二调度器，也不要求人工 kickstart。
3. 自动发现只提供候选，不可直接发布；官方网页不能切为不存在的 feed 读取器来跳过测试。
4. 发布要求与草稿哈希一致的一小时内测试，每个启用栏目通过。测试执行者可为云端，或上述经签名 Mac runtime fallback；二者使用同一 `sourceTestAllowsPublish` 结果合同和同一事务发布门禁，不存在“本机特殊放行”。事务内再次核验草稿、活动版本及测试结果，任何冲突全部回滚。重复相同发布或丢失成功回执不生成新历史版本。
5. 恢复历史只写入新草稿，保留当前活动配置；重新确认测试后才发布。不能一键绕过测试重新投产旧URL。
6. 停用坏源无需访问其故障网站；停用测试为确定性的配置检查。暂停仅控制后续采集，不删除历史文章或已存在队列。

单源最多12栏目。已发布 explicit 配置只抓指定栏目，全部纳入有限轮次预算，不按DOM顺序截为4个，也不在失败后抓首页。对于静态 HTML 只提供页面壳、且页面明确声明同源 JPaas `page/build/unit` 数据单元的站点，采集器按页面内受限参数构造同源 HTTPS 数据请求，将返回的 `data.html` 交给既有解析器；不执行站点 JavaScript、不使用浏览器采集、不降级 TLS/HTTP，也不跨主机。JPaas 分页按站点真实协议使用 `paramJson={"pageNo":N,"pageSize":20}`，只在当前页仍存在尚未处理且命中建筑主题召回的记录时继续下一页；遇到已处理相关记录页即停止，单栏目单轮硬上限为5页。达到上限只记录 partial/warning，不能把“读到5页”写成“历史已全量采集”。后台配置测试仍只验证第一页可解析性，不为发布测试遍历历史分页。尚未发布覆盖的旧种子保留过渡行为，明确显示待配置，不假称已覆盖正确栏目。

## 真实健康

健康取自既有 `building_sources_v3`。配置已发布、栏目已启用与运行正常是不同状态。显示最近检查时间；原始运行发布未提供最后成功时间、逐栏目历史和详细错误时明确显示缺失，不合成健康结果。

展开显示当前生效栏目；草稿仅在编辑器展示，避免把未生效URL说成正在采集。数据库读取失败、记录损坏和从未运行分别显示。

## 数据与恢复

沿用既有 `NEWSNOW_DB`；首次通过认证的配置写入可幂等创建四张独立表：`intelligence_source_config_entry`、`intelligence_source_config_revision`、`intelligence_source_config_test`、`intelligence_source_config_guard`。事务守卫通过 CHECK 约束使冲突在同一个 D1 batch 中失败；不采用事务外补删孤儿版本。公开GET和管理GET不执行建表。文章、签名发布状态和历史迁移标记不变。

公开 `GET /api/intelligence/building/source-config` 仅返回建筑主题已发布覆盖及SHA-256内容指纹；没有覆盖时数组为空，不等于已返回全部54个来源。草稿、测试、审计邮箱及其他主题不公开；无配置表是初始空覆盖，缺binding/部分schema/损坏记录/数据库故障返回503，不假装成功空数组。

Mac每个采集进程固定一个远程或已验证LKG配置；合并到种子后同一来源传递至列表、正文元数据和日期处理。后续补附件进程读取本轮LKG；历史旧主机原文只沿用原注册主机。缓存保留结构化配置，使用同目录独占临时文件再原子rename；失败不覆盖旧文件。校验内容指纹、每个来源及栏目、重复ID/未知ID、大小/时间/格式；远程缺项不能移除停用覆盖。远程故障保留有效LKG；缓存损坏且远程不可用时停止采集并保留原件，不静默重新启用种子。未使用缓存且首次远程不可用才使用种子。

来源ID仍须仓库登记；本版不新增任意ID，不改变签名发布静态身份白名单。更换已登记官网及栏目不需要重新部署；自定义解析器和新增读取器仍走代码PR。未完成54源栏目逐条确认不影响此工具验收，但不能称为54源全部健康。

## 验收分层

单元及内存SQLite检查验证草稿、事务、并发、测试门禁、历史恢复和LKG；临时签名密钥验证JWT正反路径；本地/CI真实Chromium验证实际生成页面、真实配置存储逻辑及合成网络结果，全程不触碰生产D1或付费AI。

上线前核对PR实际Head、changed files、类型门禁、现有回归及构建；部署后核对真实发布SHA、公开边界和匿名后台拒绝。生产管理员登录和Mac自然采用须使用新时间窗口证据，不能由CI绿色替代。Pages变量未配置时明确保持后台未启用；不声称Access配置完成等于功能上线。
