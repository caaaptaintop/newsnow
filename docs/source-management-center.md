# 信息源管理中心

## 目的

内部页面 `/internal/sources` 用于按主题维护信息源及其实际采集栏目。它不是访客管理后台：公开阅读仍免登录，内部页面和 `/internal/api/*` 必须由 Cloudflare Access 与应用端 JWT/邮箱白名单同时保护。三个环境变量缺失时，路由失败关闭为 404。

## 信息架构

- 左侧：建筑、AI、财经、健康主题及来源数量；当前只启用建筑主题的公开采集。
- 右侧：当前主题来源健康表，分别展示配置状态与运行状态。
- 来源展开：已配置栏目、语义类型、URL 和启停状态。
- 编辑抽屉：修改官网、优先级、启停、采集模式和栏目；查看历史版本并回滚。

## 配置状态

- `published`：存在已发布的 D1 版本。
- `draft`：草稿与当前发布版本不同。
- `seed`：仍使用仓库种子中的明确栏目。
- `unconfigured`：只有官网或发现模式，实际目标栏目尚未人工确认。

运行状态来自现有来源运行记录，不能用配置状态替代。没有新文章不等于异常；HTTP、TLS 和解析错误必须保留真实分类。

## 草稿、测试、发布和回滚

1. 编辑后保存草稿，或者直接点击测试；测试动作会先保存它实际测试的同一份草稿。
2. `explicit` 模式按顺序低并发读取每个启用栏目，至少识别到一篇真实文章才算该栏目通过；不保存网页 HTML。
3. `discover` 模式只返回候选栏目，不能直接作为生产明确栏目。管理员应选择候选、改为 `explicit` 后重新测试。
4. 发布要求当前草稿哈希已有成功测试，避免测试 A、发布 B。
5. 每次发布生成不可变版本；回滚会把旧配置复制成一个新的发布版本，保留审计链。

当前第一版只允许维护仓库已注册的来源 ID，不从后台创建任意新 ID。这样保持机器签名发布端的来源白名单不被绕过；后续若开放新增来源，应先把来源注册验证一并动态化。

## 采集行为

代码内来源继续作为初始 seed 和最终兜底。建筑主题已发布的 D1 配置通过只读接口 `/api/intelligence/building/source-config` 提供给 Mac 采集端。Mac 端优先刷新配置并原子写入 `.data/mac-batch/source-config.json`；网络失败时使用 last-known-good，二者均不存在才使用仓库 seed。

已发布 `explicit` 配置只读取明确栏目：栏目为空或栏目页解析不到文章时保留失败，不再回退官网首页。没有发布覆盖的旧来源暂时继续 seed 行为，避免一次上线同时切断全部 54 个来源；后续应在后台逐源确认并发布。

## 数据与安全

D1 使用三个幂等表保存草稿/活动指针、不可变发布版本和配置测试结果。首次通过鉴权访问内部 API 时创建；公共配置读取不会创建表。

配置只保存来源元数据、栏目 URL、测试摘要和最多五条标题预览，不保存原站完整 HTML、正文或附件字节。官方来源继续限制为 `.gov.cn`，栏目与官网使用同一主机，无凭据、无非标准端口。

Cloudflare 变量：

- `SOURCE_ADMIN_ACCESS_TEAM_DOMAIN`：`<team>.cloudflareaccess.com`
- `SOURCE_ADMIN_ACCESS_AUD`：Access Application Audience
- `SOURCE_ADMIN_EMAILS`：逗号、分号或换行分隔的管理员邮箱白名单

Cloudflare Access Application 使用 Host `news.capx-ai.com`、Path `internal`，覆盖父路径及子路径，不能保护整个公开站。页面为 `/internal/sources`，管理 API 为 `/internal/api/sources`。Pages 构建路由必须包含 `/internal` 和 `/internal/*`，不能由静态 SPA 回退代替服务端鉴权。

## 集成检查边界

- 配置只读接口必须通过公开 API 精确白名单；只允许 GET/HEAD，不开放管理写接口。
- 运行健康读取既有 `building_sources_v3` 的 `id/data/checked_at`，其中 `data` 才是实际 JSON 状态。当前签名发布仅保留状态、检查时间、候选数及接受数；不能据此编造历史最后成功时间、连续失败次数或栏目级失败详情。
- 只有确认来源配置表尚未建立时，公共接口才可返回空覆盖以使用种子。数据库不可用、结构不完整或活动记录损坏时应返回 503，让 Mac 保留 last-known-good，不能把错误伪装成成功的空配置。
- 显式模式最多读取全部 12 个已配置栏目，不再静默只取前 4 个；旧的自动发现过渡路径仍保持原有有限请求范围。

上述接线修正不代表完整发布验收。草稿并发保护、测试门禁、回滚行为、配置版本标识和新后台的浏览器流程仍须分别验证；完成前保持功能 PR 为 Draft，不把 Access 登录通过当成应用已上线。
